## What the code does

[FACT] `kindOf` now maps every `BvOpKind`:
- bitwise (`BNOT`, `BAND`, `BOR`, `BXOR`, `BNAND`, `BNOR`, `BXNOR`), the
  reductions `BREDAND`/`BREDOR` (1-bit result, as in Z3), `BMUL`, the five
  divisions and remainders, and the three shifts;
- `BREPEAT` and `BROTATE_LEFT/RIGHT`, with the count read from the
  unsigned first child (`BV_REPEAT`, `BV_ROLI`, `BV_RORI`);
- the nine overflow predicates, through `mkNoOverflow` (below).

It rejects three on purpose. `INT2BV`/`BV2INT` give "Bitwuzla has no
integers". `BEXT_ROTATE_*` gives "rotation by a term is not supported".
       → seahorn/lib/seahorn/Smt/MarshalBitwuzla.cc (branch bitwuzla-support, `615ef6fd`)

[FACT] The overflow encoding, as in the plan's table: SeaHorn's predicates
follow Z3, which splits signed overflow by direction
[`ExprToZ.def:261-279`]. Bitwuzla's `BV_SADD/SSUB/SMUL_OVERFLOW` are true
when the result is out of range in either direction [docs, `enums.h`].
So `mkNoOverflow` adds the direction:
- an out-of-range signed sum or difference is too large iff the first
  argument is non-negative;
- an out-of-range product is too large iff the signs agree.
The unsigned ones are just `NOT` of Bitwuzla's test.

[FACT] Arities in Bitwuzla 0.9.1 [docs, `include/bitwuzla/enums.h`]:
- 2 or more arguments: `BV_ADD`, `BV_AND`, `BV_OR`, `BV_XOR`, `BV_MUL`,
  `BV_CONCAT`;
- exactly 2: `BV_SUB`, the divisions and remainders, the shifts,
  `BV_NAND`, `BV_NOR`, `BV_XNOR`, the comparisons and the overflow tests.

SeaHorn's type rules make `BSUB`, `BMUL`, the divisions and the remainders
n-ary [`ExprOpBv.hh`, the `NOP` lines]. A 3-argument `bvsub` therefore
makes Bitwuzla throw, and the encoder turns that into `unknown`. A unit
test covers it.

## What SeaHorn builds, and what Z3's marshal does

[FACT] Grep over `lib/`, `tools/` and `include/` (`959ea729`):
- `BREPEAT`, `BROTATE_*` and `BEXT_ROTATE_*` are never built. Neither the
  Z3 nor the Yices marshal handles them.
- `BREDAND`, `BREDOR`, `BNAND`, `BNOR` and `BXNOR` are built only when Z3
  terms are converted back to `Expr` (`ZToExpr.def`, `ZToExprNoRec.cc`).
- `INT2BV`/`BV2INT` appear only in `lib/seahorn/BvInt.cc`.

[FACT] SeaHorn's type rule for `BEXT_ROTATE_*` is `Rotate`: an unsigned
amount, then a bit-vector. Z3's `ext_rotate_left` takes two bit-vectors.
This disagreement is why the encoder rejects the ext-rotates instead of
guessing.

[FACT] SeaHorn's type rule for `BREDAND`/`BREDOR` (`Unary`) gives the
argument's width, but Z3 and Bitwuzla return 1 bit. The encoder follows
Z3, since only Z3-made terms contain these operators.

[FACT] Z3's marshal reads only `zargs[0]` and `zargs[1]` for `BMUL`,
`BSUB`, `BXOR`, the divisions, the remainders, the shifts and
`BNAND/BNOR/BXNOR`. A third argument would be dropped silently
[`ExprToZ.def:217-259`]. Only `BAND`, `BOR`, `BADD` and `BCONCAT` fold
all their arguments. Our reading: opsem never builds these with more
than two arguments, or `smt-z3` would give wrong answers. So rejecting
them in Bitwuzla costs nothing in practice.

## The overflow builtins need `--with-arith-overflow`

[FACT] `sea` passes `--horn-keep-arith-overflow=false` to `seapp` unless
it is given `--with-arith-overflow` [`py/sea/commands.py:489-492`]. With
`false`, `seapp` runs `LowerArithWithOverflowIntrinsicsPass`
[`tools/seapp/seapp.cc:704-707`].

[OBS 2026-10-30] Without the flag, `overflow.c` gives "WARNING: no
assertion was found ..." and no answer, with both solvers. With it, the
final IR keeps `llvm.{umul,sadd,smul}.with.overflow`, and opsem builds the
predicates. The `test/opsem` overflow tests run `seahorn` on `.ll` files
directly, so they keep the intrinsics without the flag.

## The main build tree lost its CMake cache

[OBS 2026-10-30] `ninja -C seahorn/build` failed because
`CMakeFiles/rules.ninja` was missing:
- `CMakeCache.txt` was gone too, and only 211 object files remained.
- The tree had been touched at 19:44-19:45 on 2026-10-29, after the 1.3
  install at 18:33. A `.cmake/api/v1/query/client-vscode` folder had
  appeared.
- `URA/.vscode/settings.json` (created 19:05 that day) sets
  `cmake.sourceDirectory` to the SeaHorn checkout.
- The installed `build/run/` was intact, so `sea` kept working.

Our reading: VS Code's CMake Tools extension reconfigured `seahorn/build`
and left it without a cache. The file-API reply it wrote still listed the
original cache values (`CMAKE_CXX_FLAGS`, `BITWUZLA_HOME`,
`WITH_CLAM=OFF`, ...).

The tree was reconfigured with the same values; afterwards only 14 build
steps were needed. This is the command for `build/`, which had not been
written down before:

```sh
LLVM=/opt/homebrew/opt/llvm@18
cmake -S seahorn -B seahorn/build -GNinja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_C_COMPILER=$LLVM/bin/clang -DCMAKE_CXX_COMPILER=$LLVM/bin/clang++ \
  -DCMAKE_CXX_FLAGS="-nostdinc++ -I$LLVM/include/c++/v1 -D_LIBCPP_ENABLE_CXX17_REMOVED_UNARY_BINARY_FUNCTION" \
  -DBOOST_ROOT=/opt/homebrew/opt/boost -DLLVM_DIR=$LLVM/lib/cmake/llvm \
  -DZ3_ROOT=/opt/homebrew/opt/z3 -DCMAKE_INSTALL_PREFIX=$PWD/seahorn/build/run \
  -DBITWUZLA_HOME=$HOME/opt/bitwuzla-0.9.1 -DWITH_CLAM=OFF
```

## A mistake on the way

[OBS 2026-10-30] After the planted-bug run, the encoder was restored with
`cp -p`. That keeps the old modification time, so ninja did not recompile
it. The next `ninja install` linked the planted bugs into the installed
`seahorn`, and the unit tests failed. A `touch` and a rebuild fixed it;
all later results come from the restored code. Lesson: restore a source
file with plain `cp` (or `touch` it) before rebuilding.
